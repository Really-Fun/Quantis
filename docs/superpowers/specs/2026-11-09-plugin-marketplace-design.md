# Магазин плагинов, аккаунт Quantis и Together на токенах

Дата: 2026-11-09. Затрагивает два репозитория: программу `~/projects/Quantis`
и сайт `~/projects/QuantisSite` (Django + Channels, VPS в docker-compose).

## Зачем

- Список «Плейлисты» в левой панели не нужен, а плагины разбросаны: пункт
  «Плагины» среди разделов, страницы плагинов внизу над «Аккаунтами».
- Плагины ставятся только вручную (zip или URL). Хочется, чтобы владелец
  (админ сайта) заливал плагины на свой сайт, а пользователи ставили и
  обновляли их прямо из программы.
- Together входит на сайт, как браузер: парсит CSRF из HTML формы `/login/`
  и живёт на сессионной cookie. Это хрупко. Нужен нормальный REST API с
  токеном, общий для всего: магазина, Together и того, что появится дальше.

## Что получится (видно пользователю)

1. **Левая панель** (вариант A, выбран владельцем):
   - сверху разделы: Главная, Моя волна, Библиотека, Статистика;
   - разделитель и секция **«Плагины»**: страницы включённых плагинов
     («Вместе», «Импорт плейлистов», Cava…), последним пунктом —
     **«Менеджер плагинов»** с бейджем-числом доступных обновлений;
   - внизу: Аккаунты, Настройки;
   - секции «Плейлисты» больше нет; пункта «Плагины» среди разделов — тоже.
   - Alt+5 открывает менеджер плагинов.
2. **Менеджер плагинов** — страница с двумя вкладками:
   - «Установленные» — как нынешняя страница «Плагины»: карточки с
     переключателем, версией, автором, ошибкой; плюс кнопка «Обновить до vX»,
     если в магазине версия новее. Работает без аккаунта.
   - «Магазин» — плагины с сайта: обложка, название, автор, версия,
     описание, кнопка «Установить» / «Обновить» / «Установлено». Без входа —
     приглашение «Войдите в аккаунт Quantis» с кнопкой, ведущей в «Аккаунты».
   - Установка и обновление — без перезапуска; новый плагин сразу включается.
3. **Аккаунт Quantis** — третья карточка в «Аккаунтах» рядом с Яндексом и
   YouTube: логин и пароль от сайта → «Войти»; после входа — имя и «Выйти».
4. **Together** без своей формы входа: если аккаунта нет — заглушка
   «Войдите в аккаунт Quantis» с кнопкой в «Аккаунты»; иначе сразу список
   комнат. Пароль комнаты вводится один раз на аккаунт.

## Цели / не цели / анти-цели

**Цели:** всё выше; один вход на всё; админ заливает zip в админке и больше
ничего не заполняет.

**Не цели:** загрузка плагинов пользователями, рейтинги, комментарии,
подпись плагинов, автообновление без нажатия, платные плагины, Android-клиент,
совместимость со старыми версиями программы (старый вход Together через
форму поддерживать **не нужно** — решение владельца).

**Анти-цели (провал, даже если «работает»):**
- пароль от сайта где-то сохраняется (только токен, только в keyring);
- плагин ставится без проверки контрольной суммы или с путями вне папки;
- магазин ломает локальные/вшитые плагины или их настройки при обновлении;
- магазин виден без аккаунта или файл плагина скачивается без токена.

## Сайт (QuantisSite)

> В репозитории сайта есть незакоммиченные правки (`docker-compose.yml`,
> `nginx.conf`, `settings.py`) — это работа владельца, их не трогать и не
> откатывать; правки settings вносить поверх.

### Токены (DRF)
- Включить `rest_framework` и `rest_framework.authtoken` в `INSTALLED_APPS`
  (DRF уже в requirements). Аутентификация по умолчанию: Token + Session;
  разрешение по умолчанию: `IsAuthenticated`.
- `POST /api/auth/token/` `{username, password}` → `{token, username}`;
  неверные данные — 400 с понятным `detail`. Троттлинг входа (порядка
  10 попыток в минуту с адреса) — *моё решение*.
- `DELETE /api/auth/token/` — выход: токен удаляется.
- `GET /api/auth/me/` → `{username}` — программа проверяет токен при старте.
- Токены без срока жизни (стандартный DRF `Token`).

### Магазин
- Модель `Plugin` дополнить: `plugin_id` (slug из манифеста, уникальный),
  `sha256`, `size`. `title`, `version`, `description`, `author` заполняются
  **из `manifest.json` в zip** при сохранении в админке; ручной ввод не
  нужен. Обложка — по-прежнему необязательное поле.
- Проверка zip при сохранении (форма админки): это zip; `plugin.py` и
  `manifest.json` в корне или в единственной папке; в манифесте есть `id`
  (формат `^[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}$`) и `version`; размер не больше
  32 МБ. Иначе — ошибка формы, запись не сохраняется.
- Новая версия = загрузить новый zip в ту же запись (или в новую с тем же
  `plugin_id` — тогда старая заменяется; как именно — на усмотрение
  строителя, главное: один `plugin_id` → одна актуальная версия в API).
- `GET /api/plugins/` → список активных: `id` (plugin_id), `title`,
  `version`, `description`, `author`, `cover_url`, `download_url`, `size`,
  `sha256`, `updated_at`.
- `GET /api/plugins/<plugin_id>/download/` → zip; в проде через
  `X-Accel-Redirect`, как нынешний `DownloadPluginView`. Без токена — 401.
- Миграция: старые записи без `plugin_id` в API не попадают, пока админ не
  перезальёт их zip.
- HTML-страницы `/plugins/` остаются как есть.

### Комнаты
- Доступ к комнате с паролем хранить **за пользователем**, а не в сессии:
  модель `RoomAccess(room, user, password_version)`; `Room.has_access(user)`,
  `Room.grant_access(user)`. Веб-форма пароля тоже пишет сюда (на сайте
  все и так залогинены). Смена пароля поднимает `password_version` — старые
  доступы перестают действовать, `access_revoked` по-прежнему выкидывает из
  комнаты.
- `/api/rooms/` — DRF-вью с токеном (и сессией для браузера), формат ответа
  прежний.
- `POST /api/rooms/<id>/unlock/` `{password}` → 204 или 403.
- WebSocket: мидлварь, которая берёт пользователя из заголовка
  `Authorization: Token <key>`, иначе — из сессии (браузер). Подключить в
  `asgi.py` вокруг `URLRouter`. Нет пользователя — 4401, как сейчас.

### Тесты сайта
Токен (вход/выход/me/троттлинг), API магазина (список, 401 без токена,
скачивание), валидация zip в админке, unlock и доступ по пользователю,
WebSocket по токену.

### Выкладка
Делает владелец (на VPS сам Claude ничего не выкладывает): `git pull`,
пересборка образа, `migrate`, рестарт. Строитель кладёт пошаговую
инструкцию в README сайта или в итоговый отчёт.

## Программа (Quantis)

### Аккаунт Quantis
- Сервис аккаунта (например `quantis/services/quantis_account.py`): адрес
  сервера (по умолчанию `https://212-87-190-34.nip.io`, тот же, что сейчас у
  Together), `login(username, password)`, `logout()`, `username`, `token`,
  `is_logged_in`, сигнал «аккаунт изменился». Токен — в keyring (как токен
  Яндекса в `config/credentials.py`), имя — в QSettings. При старте токен
  проверяется через `/api/auth/me/`; 401 → считаем, что не вошли.
- Плагинам аккаунт доступен через `PluginHost` (например `host.account`):
  адрес, токен, имя, сигнал смены. Плюс способ открыть «Аккаунты» из
  плагина (например `host.open_accounts()`).
- Регистрации из программы нет: под формой ссылка «Нет аккаунта? Открыть
  сайт», ведёт на адрес сервера в браузере — *моё решение*.
- Выход удаляет токен и на сервере (`DELETE /api/auth/token/`); если сервер
  недоступен — всё равно забываем токен локально.
- Карточка в `member_page.py` в стиле существующих `_ServiceCard`. Поле
  адреса сервера — *моё решение*: спрятать под «Дополнительно», по
  умолчанию не показывать.

### Левая панель (`side_nav.py`)
- Убрать секцию плейлистов (и её подгонку `_fit_playlists`) и пункт
  «Плагины» из `CORE_TOP`.
- Под разделителем: подпись «Плагины», страницы плагинов из
  `nav_items()`, затем «Менеджер плагинов» (страница `PAGE_PLUGINS`) с
  бейджем числа обновлений (0 — без бейджа). Свёрнутая панель — только
  иконки, как у остальных пунктов.
- Плейлисты остаются в «Библиотеке» и на главной; сигнал
  `playlist_activated` и `set_playlists` можно убрать, если больше никто
  ими не пользуется.

### Менеджер плагинов (`plugins_page.py`)
- Две вкладки. «Установленные» — нынешние карточки + «Обновить до vX» +
  кнопки «Импорт из архива» и «Открыть папку» (для разработки). «Скачать по
  URL» убрать — его заменяет магазин (*моё решение*). «Удалить» плагин —
  *моё решение*: добавить, с подтверждением; вшитые (`bundled`) плагины
  удалить нельзя.
- «Магазин»: список из `/api/plugins/`, кнопка по состоянию:
  не установлен → «Установить»; версия в магазине новее → «Обновить»;
  иначе «Установлено». Установленность — по `id` из манифеста во всех
  папках плагинов (`plugin_search_dirs()`).
- Проверка обновлений: при старте (если вошли) и при открытии менеджера;
  итог питает бейдж в панели. Сравнение версий — семвер-подобно
  (`1.10.0 > 1.9.0`), не строкой.

### Установка и обновление
- Скачать zip с токеном, проверить размер и `sha256` из API, распаковать
  существующим `installer.py` (защита от zip-slip и лимиты уже есть). Папку
  назвать по `id` из API и проверить, что `id` в манифесте совпадает.
- Обновление: если плагин включён — `disable` → заменить файлы → перечитать
  метаданные → выгрузить из `sys.modules` старые модули этой папки →
  `enable`. Настройки плагина (QSettings) и состояние «включён» сохраняются.
  Сбой при обновлении — откат на прежние файлы, ошибка в уведомлении.
- Новый плагин после установки сразу включается и появляется в панели.
- Ставим всегда в пользовательскую папку (`resolve_plugins_dir()`); если
  такой же `id` есть среди вшитых, пользовательская копия главнее — *моё
  решение* (проверить порядок в `plugin_search_dirs()` и `discover()`).
- Ошибки — уведомлением через `NotificationCenter`, без модальных окон.

### Together (`plugins_dir/together`)
- Убрать форму входа, поле адреса сервера, «Запомнить пароль» и миграцию
  паролей; удалить старые записи Together из keyring при первом запуске.
- Клиент берёт адрес и токен из `host.account`; заголовок
  `Authorization: Token …` для HTTP и WebSocket; CSRF-парсинг удалить;
  пароль комнаты — через `/api/rooms/<id>/unlock/`.
- Смена аккаунта (выход, вход другим) → выйти из комнаты, перечитать
  комнаты или показать заглушку входа.
- Уведомления, звук и очередь, сделанные ранее, работают как раньше.
- Плагин живёт вне git (`plugins_dir/` в `.gitignore`) — это нормально;
  тесты плагина в `plugins_dir/together/tests`.

### Тесты программы
Сервис аккаунта (вход, выход, 401 → разлогин, токен не в QSettings),
сравнение версий, установка/обновление из zip (контрольная сумма, несовпадение
id, откат), панель без плейлистов и с бейджем, Together-клиент с токеном.
